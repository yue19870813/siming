# 司命运行时格式

司命将可编辑项目编译为与引擎无关的运行时数据。Unity、Unreal Engine 或自研宿主可选择 JSON、XML 或二进制包，不需要理解画布坐标、连线端口或编辑器状态。三种适配器消费同一个规范运行时模型。

## 导出组织方式

项目通过 `exportLayout` 选择运行时文件组织方式：

- `bundled`：全部对话合并，兼容早期宿主；旧项目未配置时使用此模式。
- `directoryChunks`：按对话源目录的第一级子目录拆分；新项目默认使用此模式，适合按章节或场景加载。

位于对话根目录的文件组成根分片。`dialogues/S01/scene/intro.json` 和 `dialogues/S01/outro.json` 都归入 `S01` 分片。

## 合并导出目录

```text
exports/runtime/
├── manifest.json
├── dialogues.runtime.json
└── locales/
    ├── zh-CN.json
    └── en-US.json
```

- `manifest.json`：格式版本、生成器版本、语言列表，以及各文件的 SHA-256 和字节数。
- `dialogues.runtime.json`：资源索引、对话入口、运行时节点和跳转目标。
- `locales/{locale}.json`：稳定文本键到最终文本的映射；缺失的非默认语言在导出时已写入默认语言回退值。
- [`runtime.schema.json`](../schemas/runtime.schema.json)：`dialogues.runtime.json` 的 JSON Schema。

相同源项目和相同格式参数会产生字节一致的文件。导出过程先写临时目录，完整成功后再替换目标目录，失败不会留下半套产物。

## 按目录拆分

JSON 示例：

```text
exports/runtime/
├── manifest.json
├── project.runtime.json
├── dialogues.runtime.json
├── dialogues/
│   └── S01/
│       └── runtime.json
└── locales/
    ├── zh-CN/
    │   ├── global.json
    │   ├── dialogues.runtime.json
    │   └── dialogues/S01/runtime.json
    └── en-US/
        ├── global.json
        ├── dialogues.runtime.json
        └── dialogues/S01/runtime.json
```

- `project.runtime.json` 是启动时读取的轻量索引，包含全局资源，以及每个对话的结构分片和语言分片路径。
- `dialogues.runtime.json` 只在对话根目录存在对话时生成。
- `dialogues/{一级目录}/runtime.json` 包含该目录及其后代中的对话结构。
- `locales/{locale}/global.json` 包含角色名称等公共文本；没有公共文本时不生成。
- 对话语言分片只包含对应结构分片使用的正文和选项文本；没有文本时不生成。

XML 使用相同目录布局并将扩展名改为 `.xml`。二进制使用 `.simingbin`，每个文件都是可独立读取和校验的容器；顶层 `runtime.simingbin` 保存项目索引和所有分片的路径、字节数与 SHA-256。

拆分模式的 JSON 契约分别由 [`runtime-index.schema.json`](../schemas/runtime-index.schema.json)、[`runtime-dialogue-chunk.schema.json`](../schemas/runtime-dialogue-chunk.schema.json) 和 [`runtime-locale-chunk.schema.json`](../schemas/runtime-locale-chunk.schema.json) 描述。

## XML 导出

```text
exports/runtime/
├── manifest.xml
├── dialogues.runtime.xml
└── locales/
    ├── zh-CN.xml
    └── en-US.xml
```

XML 使用 UTF-8 和类型化值节点：`object/field`、`array/item`、`string`、`number`、`boolean`、`null`。对象字段名保存在 `field[name]` 属性中，因此 UUID 和其他不能作为 XML 标签名的键也能无损表达。`manifest.xml` 记录协议版本、语言以及每个文件的 SHA-256。

## 二进制导出

合并模式的二进制导出生成单文件 `runtime.simingbin`；拆分模式会生成顶层索引和多个独立 `.simingbin` 分片。所有文件的包头与分段均使用大端序：

| 字段               | 类型                                                              |
| ------------------ | ----------------------------------------------------------------- |
| 魔数               | 8 字节 ASCII：`SIMINGB1`                                          |
| 包格式版本         | `u32`，当前为 `1`                                                 |
| 运行时 Schema 版本 | `u32`                                                             |
| 分段数量           | `u32`                                                             |
| 分段               | 名称长度 `u16`、UTF-8 名称、载荷长度 `u64`、SHA-256 32 字节、载荷 |

合并模式的分段名称为 `project` 和 `locale/{locale}`；拆分文件使用 `index`、`dialogues` 或 `locale`。载荷采用确定性类型编码：null、布尔、`i64/u64/f64`、UTF-8 字符串、数组和按键排序的对象。宿主读取时应先校验魔数、版本、边界和每段 SHA-256，再解析载荷。

## 节点推进规则

| 节点                         | 推进字段              | 宿主行为             |
| ---------------------------- | --------------------- | -------------------- |
| `start`、`dialogue`、`event` | `next`                | 跳转到指定 UUID      |
| `choice`                     | `choices[i].next`     | 由玩家选中的选项决定 |
| `condition`                  | `branches.true/false` | 严格求值条件后决定   |
| `end`                        | 无                    | 结束当前对话         |

每次进入节点时，先按数组顺序广播 `hostEvents`，再执行节点本身语义。宿主消息的返回值不参与分支。`event` 是项目定义的业务事件，与每个节点都可配置的宿主消息是两条独立回调路径。

## 文本与资源引用

- 对话 ID、节点 ID 使用不可变 UUID；当前 v1 导出的 `speakerId` 使用角色 Key，角色资源表按 UUID 索引。C# SDK 同时兼容角色 Key 和 UUID，并拒绝歧义引用。
- `key` 是便于日志和调试的可读别名，不作为结构引用。
- 对话正文使用 `dialogue.{dialogueId}.{nodeId}.text`。
- 选项文本使用 `dialogue.{dialogueId}.{nodeId}.choice.{choiceId}.text`。
- 角色名称使用 `character.{characterId}.name`。

运行时先加载当前语言文件，通过 `textKey` 或 `nameKey` 取值。导出产物已完成语言回退；找不到键应视为产物损坏并停止该条对话。

## CLI

```bash
siming validate . --format json
siming validate . --warnings-as-errors
siming export . --output exports/runtime --format json --pretty
siming export . --output exports/runtime --format xml --pretty
siming export . --output exports/runtime --format binary
siming export . --output exports/runtime --layout directory-chunks
siming export . --output exports/runtime --layout bundled
siming migrate . --check
siming migrate . --write
siming info . --format json
```

退出码为：`0` 成功、`1` 校验失败、`2` 参数/路径/版本错误、`3` 未预期内部错误。迁移写入前自动备份；桌面端执行迁移前还会要求用户确认。

## 宿主接入示例

[`examples/runtime-reader/index.mjs`](../examples/runtime-reader/index.mjs) 同时支持合并和目录拆分的 JSON 产物。拆分模式会先读取项目索引，再按 dialogue key 只加载对应结构分片与当前语言分片：

```bash
node examples/runtime-reader/index.mjs exports/runtime prologue zh-CN
```

示例只用于说明数据契约，不是 Unity/UE 官方 SDK。正式宿主应补充资源缓存、异步事件、存档恢复和错误上报。

## C# SDK

首版 C# SDK 提供 JSON 合并/分片加载、剧情状态机、变量与异步事件、多语言，以及由宿主保存的最小播放状态接口。Unity 6 接入包与通用 .NET 库使用相同核心源码，详见 [SDK 接入文档](../sdks/csharp/README.md)。
