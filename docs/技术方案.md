# 司命（Siming）剧情对话编辑器技术方案

> 文档定位：本方案是 [`产品需求文档.md`](./产品需求文档.md) 的技术实现基线，面向桌面端、共享核心、CLI、测试与游戏宿主接入开发。需求范围以 PRD 为准；本方案负责固定模块边界、数据契约、持久化位置、异常处理和验收方法。
>
> MVP 平台：Windows、macOS、Linux 桌面应用与独立 CLI。PRD 概述中若出现平台枚举遗漏，以 PRD 的“跨平台要求”、MVP 验收总表及本方案为准。

## 一、项目概述

Siming 是一个脱离游戏引擎运行的通用剧情对话编辑器，面向叙事设计师和游戏开发者，用于可视化配置带有分支与条件判断的剧情对话。

编辑器负责对话内容的创建、组织、校验、预览和导出；游戏侧负责读取导出数据，并自行实现 UI、角色表现、音频播放及具体业务逻辑。

### 1.1 核心诉求

- 通过节点画布编辑对话树，支持拖拽、连线、缩放和布局。
- 可在画布、表格与数据视图之间切换，分别用于结构编辑、顺序阅读和直接编辑对话源 JSON。
- 支持普通对话、玩家选项、条件分支和剧情结束等基本流程。
- 使用与游戏引擎无关的 JSON 数据格式，方便 Unity、Unreal 或自研引擎接入。
- 在同一份对话中维护多语言文本，并按语言预览、校验和导出。
- 内置模拟运行功能，无需启动游戏即可检查分支、条件和对话顺序。
- 提供无界面的命令行模式，支持在 CI 和批处理流程中校验、导出和检查项目。
- 支持 Windows、macOS 和 Linux，项目文件可由 Git 等版本控制工具管理。

### 1.2 设计原则

- **内容与表现分离**：数据描述“说什么、何时分支、触发什么”，不约束游戏内 UI 和演出方式。
- **编辑数据与运行数据分离**：画布坐标等编辑器信息不进入最终运行时数据。
- **显式且可校验**：节点、连线、条件和变量均有明确结构，尽量在导出前发现错误。
- **稳定优先**：文件格式带版本号；节点使用自动生成、不可变的 UUID 作为内部 ID，并保留可读 Key，避免手工编号冲突或调整布局造成无意义的数据变更。
- **渐进扩展**：先完成包含基础多语言能力的单机 MVP，再扩展翻译平台协作、多人协作和引擎插件。

### 1.3 MVP 范围

MVP 包含以下能力：

1. 创建、打开、保存对话项目。
2. 在设置中心分别管理可共享的项目设置和仅保存在本机的用户设置，并支持相对项目根目录配置对话与导出目录。
3. 使用真实目录树创建和管理多个对话文件，并通过智能分组查看最近编辑、错误和翻译状态。
4. 编辑开始、对话、选项、条件、事件和结束节点。
5. 创建、删除和修改节点之间的连线。
6. 查看并编辑当前对话的真实源 JSON，在应用修改前执行语法与 Schema 校验。
7. 通过独立资源界面管理角色、变量、事件和标签定义，并查看它们在项目中的引用。
8. 撤销、重做、复制、粘贴、搜索和基础快捷键。
9. 校验对话图并定位错误节点。
10. 从任意入口模拟运行对话，并临时修改变量观察分支结果。
11. 配置项目默认语言和支持语言，在同一节点中编辑、切换和预览多语言文本。
12. 校验缺失翻译，并按稳定文本键导出各语言资源。
13. 导出与引擎无关的 JSON、XML 或二进制运行时数据，并支持目录分片。
14. 通过命令行执行项目校验、导出、迁移检查和项目信息查询。
15. 构建 Windows、macOS 和 Linux 桌面应用及命令行程序。

以下能力暂不纳入 MVP：

- 多人实时协作、云同步和账号系统。
- 游戏内 UI、立绘、动画、Timeline 或音频播放。
- 完整脚本语言及任意代码执行。
- Excel、CSV、XLIFF、Ink、Yarn Spinner 等第三方格式的双向转换。
- Unity、Unreal 的官方运行时插件。
- 翻译平台同步、机器翻译、术语库、翻译审核和配音资产管理。
- 编辑器界面多语言；MVP 只保留设置入口和可扩展配置结构，界面文案仍以中文交付。
- 在终端中交互式创建或编辑节点图。

## 三、总体架构

应用采用“React 桌面界面 + Tauri 桌面适配层 + Rust 共享核心 + Rust CLI + 本地项目文件”的结构。桌面端和命令行端共用同一套校验、迁移与导出实现。

```text
┌────────────────────────────┐   ┌──────────────────────────┐
│ React 桌面界面             │   │ siming CLI               │
│ 画布 │ 表格 │ 数据 │ 属性   │   │ validate │ export │ info │
└─────────────┬──────────────┘   └────────────┬─────────────┘
              │ Tauri IPC                     │ CLI 适配层
┌─────────────▼────────────────────────────────▼─────────────┐
│ Rust 共享核心业务层（siming-core）                         │
│ 数据模型 │ Schema │ 完整校验 │ 条件求值 │ 编译导出 │ 迁移   │
├────────────────────────────────────────────────────────────┤
│ 共享存储层（siming-storage）                               │
│ 项目读取 │ 路径校验 │ 原子写入 │ 备份                       │
├────────────────────────────────────────────────────────────┤
│ 本地文件系统                                               │
│ 项目配置 │ 对话源文件 │ 角色/变量定义 │ 导出文件             │
└────────────────────────────────────────────────────────────┘
```

### 3.1 前端职责

- 渲染应用界面、节点画布、顺序阅读表格、数据编辑器和属性表单。
- 维护当前文档、选择状态、视口状态和撤销历史。
- 维护数据编辑草稿，在用户确认应用前不覆盖当前有效文档。
- 执行不改变业务语义的即时交互约束，例如端口是否已连接和必填字段提示。
- 通过 Tauri IPC 调用权威校验、条件求值、编译导出、迁移和文件能力。

### 3.2 Rust 共享核心职责

- 定义项目、节点、条件、多语言文本和运行时导出的权威数据模型。
- 实现完整校验、条件求值、文本回退、稳定文本键和运行时编译。
- 实现 Schema 版本检测与纯数据迁移。
- 不依赖窗口、终端和具体文件对话框，保证桌面端与 CLI 结果一致。

### 3.3 桌面与存储层职责

- 打开项目目录、读取源文件和列出项目资源。
- 使用临时文件加替换方式原子保存，避免写入中断损坏源文件。
- 提供文件选择、最近项目和应用配置等桌面能力。
- 限制文件访问范围，不向前端暴露任意命令执行能力。

### 3.4 CLI 职责

- 解析命令行参数，读取项目并调用共享核心。
- 将命令结果按所选格式写到标准输出流，将运行日志和非结果错误写到标准错误流。
- 使用稳定退出码表达成功、校验失败、输入错误和内部错误。
- 默认无交互运行；会改写文件的操作必须显式传入写入参数。

### 3.5 边界约束

- 权威业务规则只在 `siming-core` 实现，React 和 CLI 不各自复制一套校验或导出规则。
- React 可实现即时交互提示，但最终结果必须以共享核心返回值为准。
- TypeScript 类型、JSON Schema 与 Rust 数据模型通过代码生成或契约测试保持一致。
- 所有 IPC 命令使用明确的输入输出类型，并在前后端边界执行数据校验。
- `siming-core` 不读取用户主题、窗口布局、最近项目或其他本机偏好，确保同一项目在不同成员设备上产生相同诊断和导出结果。
- 文件系统写入只由 `siming-storage` 执行；前端不得直接拼接绝对路径，CLI 也不得绕过路径规范化和原子写入。
- 运行时编译结果是 JSON、后续 XML/二进制等格式适配器的共同输入；格式适配器不得重新解释节点分支语义。

### 3.6 建议代码组织

```text
siming/
├── apps/
│   └── desktop/              # React 前端与 Tauri 桌面适配层
├── crates/
│   ├── siming-core/          # 数据模型、校验、求值、导出与迁移
│   ├── siming-storage/       # 项目读取、路径检查、原子写入与备份
│   ├── siming-runtime/       # 引擎无关运行时模型、步进协议与宿主回调契约
│   └── siming-cli/           # siming 命令行程序
├── schemas/                  # 对外发布的 JSON Schema
├── fixtures/                 # GUI、CLI 和迁移共用的契约测试项目
├── adr/                      # 关键架构决策记录
└── docs/
```

`siming-runtime` 只定义可被各语言 SDK 复刻的纯数据协议和状态机，不包含 Unity、Unreal Engine API。MVP 可以先作为 `siming-core` 内部模块实现；当官方 SDK 进入路线图时再拆分为独立 crate，避免过早增加发布单元。

## 四、功能模块

### 4.1 项目管理

- 新建项目时生成项目清单、默认角色和第一份对话文件。
- 打开项目时先校验格式版本，再加载项目索引和目标对话。
- 记录最近打开的项目，但不将本机绝对路径写入项目源文件。
- 项目内文件使用相对路径，保证跨设备和版本控制可用。

### 4.2 对话文件管理

- 一个项目可包含多份对话，每份对话拥有自动生成、不可变的 UUID、可读 Key、显示名称、相对路径和入口节点。
- 每份对话还可维护描述和标签，用于说明剧情目标、场景、章节或内容分类；标签不参与运行时分支判断。
- 左侧对话区使用与 `dialogues/` 真实磁盘目录一致的树形结构，支持创建、重命名、展开、收起和删除空文件夹。
- 支持拖拽对话到其他目录；移动或重命名只更新项目清单中的相对路径，不修改对话 UUID、跨文件引用和文本键。
- 目录最多建议 3 层；更复杂的交叉分类使用标签和智能分组，不继续增加目录深度。
- 提供“全部对话、最近编辑、存在错误、翻译未完成、未被引用”等虚拟分组；虚拟分组不改变磁盘路径。
- 支持创建、重命名、复制和删除对话；删除前明确提示该操作影响的文件和跨文件引用。
- 对话列表提供名称、UUID、Key、标签和路径搜索，并显示未保存、警告和错误状态。

### 4.3 项目搜索

- 左侧主导航提供独立的项目搜索入口，打开后使用完整工作区展示搜索条件与结果，不复用节点画布。
- 支持按对话文件、节点和项目资源筛选，并搜索显示名称、稳定 ID、对白文本、条件表达式和事件名称。
- 搜索结果按内容类型分组，展示所属文件或资源类型；点击结果直接定位节点或打开对应资源定义。
- 搜索框与侧边栏快速搜索保持同步，并提供 `Command/Ctrl + K` 快捷入口。

### 4.4 项目资源编辑器

项目资源包括角色、变量、事件和标签。四类资源使用统一的“资源列表 + 搜索/新增 + 右侧属性编辑”布局，并根据资源类型展示不同字段。

**角色编辑器：**

- 列表展示角色头像色、稳定 ID、当前语言显示名、标签和对白引用次数。
- 属性区编辑多语言显示名、简称、主题色、描述和自定义标签。
- 点击引用次数可列出使用该角色的对话和节点，并支持跳转定位。

**变量编辑器：**

- 列表展示变量键、类型、默认值、作用域和读写引用次数。
- 属性区编辑 `boolean`、`number`、`string` 类型及对应默认值、说明和可选数值范围。
- 修改类型时先检查已有条件与事件参数；不兼容的引用会阻止保存。

**事件编辑器：**

- 列表展示事件名、显示名称、参数数量、分类和引用次数。
- 属性区编辑事件说明及参数 Schema；每个参数包含名称、类型、是否必填、默认值和说明。
- 内置事件标记为系统定义，可查看但不能删除；项目自定义事件允许复制和删除。

**标签编辑器：**

- 最左侧主导航和“项目资源”列表均提供标签管理入口，并打开同一个标签编辑器。
- 标签定义包含稳定 ID、显示名称、颜色、适用范围和说明；适用范围可限制为对话文件、节点、项目资源或全部内容。
- 标签可用于目录之外的交叉分类、搜索和智能筛选，但不参与运行时条件判断。
- 列表展示颜色、适用范围、说明和引用次数；点击引用可定位使用该标签的对话、节点或资源。
- 删除前检查全部引用，存在引用时阻止删除；重命名显示名称不改变稳定 ID 和已有引用。

通用规则：

- 稳定 ID 或键在创建后默认不可直接修改；需要改名时执行带引用更新的重命名操作。
- 删除前检查全部引用：存在引用时阻止删除，并提供引用列表；未引用资源需二次确认。
- 支持新增、复制、搜索、按类型筛选和按引用次数排序。
- 资源修改进入统一撤销/重做与未保存状态，并实时影响节点属性下拉选项和校验结果。
- 每类资源均可切换到数据视图，编辑对应的 `characters.json`、`variables.json` 或 `events.json`，沿用源 JSON 草稿与校验机制。

### 4.5 项目与用户设置

设置中心区分“项目设置”和“用户设置”，界面必须持续显示当前配置的作用范围，避免将本机偏好误提交到项目仓库。

**项目设置：**

- 项目设置写入项目内的 `.siming/project.json`，可纳入版本控制，由桌面端和 CLI 共同读取。
- 可配置对话文件目录、导出文件目录、默认导出格式、默认语言和支持语言等项目级选项。
- 项目根目录的本机绝对路径只用于解析相对路径，不写入项目配置；“最近项目”仅保存于本机用户配置。
- 对话和导出目录默认使用相对于项目根目录的路径，例如 `dialogues/` 和 `exports/runtime/`，保证项目移动到其他设备后仍可工作。
- 项目配置只持久化相对路径。路径输入框可接受绝对路径用于选择和预览，但若目标位于项目根目录内，保存时必须转换为相对路径；若目标位于项目外，只能作为当前设备的用户级覆盖项保存，不得写入 `.siming/project.json`。
- 相对路径统一使用 `/` 作为分隔符，保存前执行规范化；默认禁止路径通过 `..` 逃逸项目根目录。
- 应用设置前校验目录是否合法、目标是否可写以及路径是否冲突；需要创建目录时须明确提示，校验失败不得覆盖现有配置。
- 项目设置采用“编辑草稿 → 校验 → 原子应用”流程；修改对话目录时必须先扫描目标目录并生成移动计划，不能只改配置而遗留旧文件。

**用户设置：**

- 用户设置仅保存在当前设备，不进入项目目录和版本控制。
- 可配置新项目默认保存位置、界面语言预留项、`Dark`/`Light` 主题、数据编辑器字号、快捷键方案、自动恢复快照间隔和启动时是否恢复上次项目。
- 主题设置仅保存在本机，切换后立即作用于整个编辑器；重新打开应用时恢复上次选择，恢复用户默认设置时回到 `Dark`。
- 主题枚举在配置层固定为 `dark | light`，不接受 `system` 或其他值；读取未知值时回退为 `dark` 并记录可诊断警告。
- 主题通过根元素 `data-theme` 和语义化设计令牌切换，组件禁止硬编码只适用于深色背景的前景色。节点类型色属于业务语义色，在两种主题下分别提供满足对比度的令牌。
- “自动保存”在 MVP 中实现为应用数据目录中的恢复快照，不静默覆盖项目源文件；用户主动保存、确认外部修改或执行迁移时仍遵循原子写入流程。
- 界面语言设置在 MVP 中仅作为后续能力入口，不承诺切换编辑器文案；项目内容语言继续由项目设置管理。
- 用户设置不得改变项目导出结果；项目设置与用户设置存在同名概念时，以清晰分组和作用域说明消除歧义。

建议的本机配置结构如下，实际物理位置由 Tauri 的应用配置目录解析：

```json
{
  "schemaVersion": 1,
  "theme": "dark",
  "defaultProjectDirectory": "/Users/example/Projects",
  "projectOverrides": {
    "2fd88ddc-aa3b-466f-92a2-48785adce71e": {
      "exportDirectory": "/Volumes/build/dialogues"
    }
  },
  "editorFontSize": 13,
  "keymap": "platform",
  "recoverySnapshotIntervalSeconds": 60,
  "restoreLastProject": true
}
```

### 4.6 画布与表格视图

- 支持框选、多选、拖拽、连线、缩放、平移、适应视图和小地图。
- 鼠标滚轮默认缩放；触摸板捏合缩放；在画布空白区域按住鼠标中键、空格加左键或双指拖动执行平移。节点上的滚动控件必须阻止事件冒泡，避免编辑表单时误缩放画布。
- 视口缩放范围建议限制为 `0.2–2.0`，缩放围绕指针位置计算；“适应视图”根据当前筛选后的全部节点边界计算，并保留安全边距。
- 支持复制粘贴节点；粘贴时为节点和内部连线生成新 ID。
- 节点删除、移动、字段修改和连线操作全部进入统一撤销/重做历史。
- 画布只负责交互，节点结构和连线合法性由共享核心业务层判断。
- 表格视图按对话图的拓扑顺序排列节点，提供顺序、路径、类型、角色与正文、进入条件和下一节点等列，方便连续阅读和审校对白。
- 玩家选项使用 `A`、`B` 等路径标签，条件分支使用 `TRUE`、`FALSE` 标签；分支后续节点继承对应标签，并通过缩进和颜色保持路径连续性。
- 多条路径到达同一节点时只展示一次该节点，并标记“汇合”及来源路径，避免为了阅读而复制节点内容。
- 存在循环时不无限展开：循环节点只展示一次，并在进入条件或下一节点列标明回跳目标。
- 点击表格行应选中同一节点并与右侧属性编辑器联动；画布与表格共享选择状态、当前预览语言和同一份文档模型。
- 表格顺序由稳定遍历算法生成：从入口开始，按节点类型定义的端口顺序深度优先展开；选项按 `choices[]` 顺序，条件固定按 `true` 后 `false`。同一节点第二次被访问时输出“汇合/回跳引用行”而非复制实体行。
- 表格中的顺序号是阅读视图编号，不写回源文件，也不能作为运行时跳转依据。

### 4.7 数据结构编辑器

- 当前对话提供“画布”“表格”和“数据”三种视图，三者对应同一份编辑源模型，不维护独立副本。
- 数据视图默认展示当前对话源 JSON，包括节点、连线、画布坐标、多语言文本、内部 UUID 和可读 Key。
- 同时提供只读的“运行时预览”，展示移除编辑器字段并拆分多语言文本后的编译结果。
- 支持 JSON 语法高亮、行号、折叠、搜索、括号匹配、自动缩进和一键格式化。
- 用户在数据视图中的输入先进入独立草稿；只有 JSON 解析和 Schema 校验通过后，“应用修改”按钮才可用。
- 应用修改时由共享核心执行完整校验，并将差异作为一个原子操作写入文档及撤销历史。
- 解析或 Schema 校验失败时保留草稿和错误位置，不改变画布中的最后有效数据，也不允许保存或导出该草稿。
- 离开数据视图、切换对话、保存、导出和关闭项目时若存在未应用草稿，统一弹出“应用修改 / 放弃草稿 / 继续编辑”；任何入口不得绕过此拦截。
- 草稿只写入自动恢复快照，不写入项目文件；恢复时同时呈现最后有效文档和未应用草稿，避免把无效 JSON 当作已保存内容。
- 画布中选中节点后切换到数据视图，应定位该节点对象；数据诊断也可反向定位画布节点。
- 数据视图只允许编辑项目源结构，不允许执行 JSON 中的脚本、命令或动态代码。

### 4.8 属性编辑器

- 根据节点类型展示对应字段，并对必填项、类型和引用进行即时校验。
- 未选中节点时默认展示当前对话文件的属性，包括名称、UUID、Key、描述、标签、文件路径和内容统计；点击画布空白处可取消节点选择并返回该状态。
- 选中画布节点或表格行后切换为节点属性；画布、表格和属性面板共享同一选择状态。
- 每种节点都提供可选的“宿主消息（Host Events）”列表，每条消息包含名称和 JSON 参数，并支持新增、删除和调整广播顺序；它们是节点进入通知，不等同于业务事件节点。
- 角色、变量、事件和标签通过受控选择引用已有定义，避免自由文本造成拼写差异。
- 对高级参数保留 JSON 值类型，但不允许执行任意 JavaScript 或系统命令。

### 4.9 校验中心

校验分为错误和警告：错误会阻止导出，警告允许导出但需要显式展示。

诊断必须使用稳定代码而不是文案作为程序判断依据：

```ts
type Diagnostic = {
  code: string; // 例如 NODE_DUPLICATE_ID
  severity: "error" | "warning";
  message: string; // 面向当前界面语言的说明
  file: string; // 项目相对路径
  entityType?: "dialogue" | "node" | "edge" | "resource" | "locale";
  entityId?: string;
  fieldPath?: string; // JSON Pointer，例如 /nodes/3/data/text/zh-CN
  range?: {
    line: number;
    column: number;
    endLine?: number;
    endColumn?: number;
  };
  related?: Array<{ file: string; entityId?: string; fieldPath?: string }>;
};
```

- 校验分为语法、Schema、引用、图结构、表达式、多语言和导出前检查七个阶段；前一阶段无法建立可信模型时，后续阶段可以跳过并返回明确原因。
- 校验结果按严重级别、文件路径、实体位置和诊断代码稳定排序，保证 GUI、CLI 与快照测试输出一致。
- 点击问题优先通过 `entityId` 定位实体；数据视图语法错误则使用 `range` 定位；跨文件引用问题通过 `related` 展示来源与目标。
- “重新校验”使用当前最后有效文档；未应用草稿单独显示草稿诊断，不能与项目诊断混为一组。

**错误示例：**

- 缺少唯一开始节点或存在多个开始节点。
- 必填文本为空、节点 UUID 或 Key 重复、UUID 格式错误或引用不存在。
- 必须有出口的节点没有有效连线。
- `start`、`dialogue` 或 `event` 存在多个出口，或出口端口不是 `next`。
- 同一选项存在多个无法确定优先级的出口。
- 选项缺少同名出口，或条件节点缺少 `true`、`false` 任一分支。
- 条件表达式类型不匹配或引用未定义变量。
- 默认语言的必填文本缺失。
- 变量默认值与类型不匹配，或事件参数定义不合法。

**警告示例：**

- 存在从入口不可到达的节点。
- 存在没有退出路径的循环。
- 角色、事件或变量已定义但未使用。
- 非默认语言存在缺失翻译，运行时将回退到默认语言。
- 对话文本可能超过建议长度。

点击校验项后，画布应定位并选中对应节点或连线。

### 4.10 模拟运行器

- 从入口节点或当前选中节点开始运行。
- 展示当前说话人、对话内容、可选项和已执行事件。
- 可切换预览语言；发生默认语言回退时标记对应文本。
- 提供变量面板，可在测试期间修改变量并重新计算条件分支。
- 记录本次运行经过的节点和条件结果，便于定位错误。
- 模拟器只修改内存中的运行上下文，不回写项目变量默认值。
- 设置最大连续步数，检测没有等待用户输入的无限循环。
- 每次进入节点的固定顺序为：更新 `currentNodeId` → 依序记录并广播 `hostEvents` → 执行节点自身语义 → 进入下一节点或等待玩家输入。
- 对业务事件节点，模拟器调用可替换的测试执行器；未配置执行器时记录“已模拟”日志并继续，不执行项目中的任意脚本。
- 连续自动推进默认上限建议为 1,000 步；玩家每次选择或手动继续后重新计算连续步数，但总轨迹仍保留访问序号，方便识别跨交互循环。
- 模拟日志至少包含时间顺序、节点 UUID/Key、条件输入与结果、玩家选择、业务事件、宿主消息索引和语言回退信息。

### 4.11 多语言编辑

- 项目必须设置一个默认语言，并可配置多个支持语言；语言代码使用 BCP 47 形式，例如 `zh-CN`、`en-US`。
- 对话正文、选项文本和角色显示名使用统一的多语言文本结构。
- 属性面板固定显示默认语言，并允许切换或并排编辑其他语言。
- 画布和搜索默认使用当前预览语言；缺失时显示默认语言并附加回退标记。
- 默认语言文本为必填；其他语言允许暂时缺失，但必须进入校验结果和翻译完成度统计。
- 删除语言配置前提示该语言已有文本数量，确认后才移除对应内容。
- MVP 的多语言范围是项目内容，不要求 Siming 应用界面本身支持多语言切换。

多语言字段统一表示为：

```ts
type LocalizedText = Record<string, string>;

const example: LocalizedText = {
  "zh-CN": "故事从这里开始。",
  "en-US": "The story begins here.",
};
```

运行时回退规则固定为：请求语言文本 → 项目默认语言文本 → 返回缺失文本错误。MVP 不实现 `zh-Hant-TW → zh-Hant → zh` 等语言层级推导，避免编辑器与各引擎产生不同结果。

### 4.12 导出器

导出过程分为七步：

1. 拦截未应用的数据草稿。
2. 校验项目和目标对话；存在 `error` 时拒绝导出。
3. 将编辑器模型编译为语言无关的规范运行时模型。
4. 使用稳定文本键提取各语言文本资源。
5. 移除画布坐标、折叠状态等编辑器专用字段。
6. 按稳定字段和实体顺序序列化，保证相同输入产生字节一致结果。
7. 由存储层写入临时目录，全部文件成功后再替换目标导出目录，避免只更新一部分产物。

导出器支持 JSON、XML 和二进制，三种格式适配器消费同一规范运行时模型，不直接读取编辑器源文件。`bundled` 布局保持全项目合并产物；`directoryChunks` 由核心层按对话一级目录生成统一分片模型，格式适配器只负责序列化。拆分模式的项目索引保留全局资源和对话到结构、语言分片的路径，宿主启动时读取索引，进入章节或场景时再加载目标分片。

确定性序列化规则：

- 对象字段按 Schema 定义顺序输出；按 UUID 索引的节点对象按 UUID 字典序输出。
- `choices[]`、`hostEvents[]` 等具有业务顺序的数组保持源顺序，不做排序。
- 不输出 `null` 形式的可选字段；浮点数禁止 `NaN`、`Infinity`，并使用跨平台一致的 JSON 表示。
- 文本统一按 UTF-8 输出，换行使用 `LF`；`--pretty` 只改变空白，不改变数据语义。
- 导出清单记录 `runtimeSchemaVersion`、生成器版本和文件哈希，但不写入时间戳等导致不可重复构建的字段。
- 旧项目缺少 `exportLayout` 时使用 `bundled`；新项目默认 `directoryChunks`。
- 二进制拆分模式输出多个独立容器，每个容器都包含魔数、版本、长度和分段 SHA-256，不要求宿主支持随机读取。

### 4.13 命令行模式

CLI 可执行文件名为 `siming`，默认使用当前目录作为项目路径，也可显式传入路径。MVP 提供以下子命令：

```bash
# 校验项目；默认输出适合阅读的诊断信息
siming validate ./example-project

# 为 CI 输出结构化结果，并将警告视为失败
siming validate ./example-project --format json --warnings-as-errors

# 导出全部对话及语言资源
siming export ./example-project --output ./build/dialogues

# 使用缩进格式输出；不传时采用紧凑、确定性 JSON
siming export ./example-project --output ./build/dialogues --pretty

# 临时覆盖项目的导出组织方式
siming export ./example-project --layout directory-chunks

# 仅检查项目是否需要迁移，不改写文件
siming migrate ./example-project --check

# 执行迁移；写入前自动备份
siming migrate ./example-project --write --backup-dir ./migration-backups

# 查看项目版本、语言、对话数量及校验摘要
siming info ./example-project --format json
```

CLI 约定：

- `validate` 和 `info` 只读；`export` 只写入指定导出目录。
- `migrate` 默认等价于 `--check` 并只报告状态；只有提供 `--write` 才能改写源项目，`--backup-dir` 可指定备份目录。
- `--format text` 面向用户阅读，`--format json` 面向 CI 和其他工具消费。
- `export --output`、`--format` 和 `--layout` 可临时覆盖项目默认配置，但只影响本次命令；`--pretty` 只改变文本格式排版。
- JSON 模式下，标准输出只包含一个完整 JSON 文档；日志和诊断摘要写入标准错误流。
- 诊断结果包含稳定的 `code`、`severity`、文件相对路径、节点 UUID、可读 Key 和消息，方便 CI 精确定位。
- CLI 和桌面端使用相同配置、Schema、校验、迁移和导出代码。

退出码约定：

| 退出码 | 含义                                                   |
| ------ | ------------------------------------------------------ |
| `0`    | 命令成功，且不存在会导致失败的诊断                     |
| `1`    | 项目校验失败，或启用 `--warnings-as-errors` 后存在警告 |
| `2`    | 参数错误、项目无法读取、版本不受支持或输出路径无效     |
| `3`    | 未预期的内部错误                                       |

桌面安装包和 CLI 作为两个产物发布。CLI 不依赖桌面窗口或前端资源，可单独用于构建服务器；安装脚本或包管理器集成不属于 MVP，首期提供压缩包和校验值。

## 五、节点与连线设计

### 5.1 MVP 节点类型

| 类型        | 用途               | 入口       | 出口规则                |
| ----------- | ------------------ | ---------- | ----------------------- |
| `start`     | 对话入口           | 无         | 必须且只能有 1 个       |
| `dialogue`  | 角色对白或旁白     | 1 个或多个 | 必须且只能有 1 个       |
| `choice`    | 玩家可选分支       | 1 个或多个 | 每个选项对应 1 个出口   |
| `condition` | 按变量判断走向     | 1 个或多个 | `true`、`false` 各 1 个 |
| `event`     | 通知游戏侧执行事件 | 1 个或多个 | 必须且只能有 1 个       |
| `end`       | 结束当前对话       | 1 个或多个 | 无                      |

编辑源节点共享 `id`、`key`、`type`、`position`，节点业务数据统一放在 `data` 中，其中可包含 `hostEvents`、标签及推进策略；需要等待或自动推进的可呈现节点使用明确的推进策略：

```ts
type AdvancePolicy = { mode: "manual" } | { mode: "auto"; delayMs: number };
```

MVP 不使用 `0`、空字符串或缺失字段隐式推断推进方式。`delayMs` 必须是非负有限整数；`start`、`condition`、`event` 默认立即执行流程语义，`end` 终止运行，不能配置推进策略。

### 5.2 节点标识

- 每个节点包含 `id` 和 `key`：`id` 是编辑器自动生成、创建后不可修改的 UUID v4；`key` 是面向作者的可读别名。
- 新建、复制和导入节点时必须生成新的 UUID；复制操作不得沿用源节点 UUID。
- `key` 可由用户修改，但必须以字母开头，并在当前对话文件内唯一；修改 Key 不影响连线。
- 对话入口、连线、跨文件引用和运行时索引统一使用 UUID，避免 Key 重命名导致引用失效。
- 属性编辑器默认展示 Key，并在高级信息中提供只读 UUID 与复制操作；源数据视图允许查看 UUID，但修改时必须进行强校验。
- 读取不含 UUID 的旧项目时，由迁移程序生成 UUID 并一次性重写入口和连线引用。
- 选项 ID 同样由编辑器生成并在所属 `choice` 节点内不可变；修改选项文案或排序不会改变 ID、连线和文本键。

### 5.3 连线规则

- 连线以 `sourceNodeId`、`sourcePort`、`targetNodeId` 和 `targetPort` 表示，其中节点引用统一保存 UUID。
- 节点端口决定语义，例如条件节点固定使用 `true` 和 `false` 出口。
- `start`、`dialogue` 和 `event` 必须且只能使用一个 `next` 出口；`end` 不允许存在出口。
- `choice` 的 `sourcePort` 必须等于对应选项 ID，每个选项恰好连接一个目标节点。
- `condition` 必须同时具有且仅具有 `true`、`false` 两个出口；不得依赖连线数组顺序表达真假分支。
- 默认禁止无意义的自连接；循环必须经过明确的多个节点路径。
- 新建连线时即时检查端口数量、类型和重复连接。
- 删除带引用的端口或选项时，同时删除对应连线并进入同一撤销操作。

### 5.4 条件表达式

MVP 不引入可执行脚本，使用结构化条件表达式：

```json
{
  "all": [
    { "variable": "favor", "operator": ">=", "value": 10 },
    { "variable": "hasKey", "operator": "==", "value": true }
  ]
}
```

首期支持：

- 变量类型：`boolean`、`number`、`string`。
- 比较运算：`==`、`!=`、`>`、`>=`、`<`、`<=`。
- 逻辑组合：`all`、`any`、`not`。
- 字符串只允许 `==` 和 `!=`；大小比较只用于数字。

结构化表达式便于表单编辑、静态校验，并可由不同游戏引擎一致实现。

### 5.5 事件设计

事件用于向游戏侧发送声明式指令，例如设置变量、开始任务或播放演出：

```json
{
  "event": "quest.start",
  "params": {
    "questId": "find_the_key"
  }
}
```

编辑器只校验事件名称和参数是否符合项目内的事件定义，不执行游戏逻辑。MVP 内置 `variable.set`、`variable.add`，其他事件由项目自行定义。

运行时通过独立的 `executeBusinessEvent(event, context)` 回调处理业务事件。执行器可以异步完成，事件节点在成功完成后读取单一 `next`；执行失败则暂停运行并返回结构化运行错误，不自动选择备用分支。MVP 不根据回调业务返回值直接选择分支。若事件需要影响后续条件，应通过声明过的变量写入接口更新运行上下文，再由后续 `condition` 节点读取。

### 5.6 节点宿主消息

所有节点类型均可配置零到多个宿主消息，用于在运行时向 Unity、Unreal Engine 或其他上层宿主广播节点生命周期通知：

```json
{
  "hostEvents": [
    {
      "name": "ui.portrait.show",
      "payload": {
        "position": "left",
        "emotion": "serious"
      }
    },
    {
      "name": "camera.focus",
      "payload": {
        "target": "dur",
        "duration": 0.35
      }
    }
  ]
}
```

宿主消息列表与 `event` 业务事件节点采用不同字段和语义：

| 对比项   | 宿主消息 `hostEvents`              | 业务事件节点 `event`              |
| -------- | ---------------------------------- | --------------------------------- |
| 所属范围 | 任意节点的可选附加配置             | 独立的流程节点类型                |
| 触发时机 | 每次进入该节点时广播               | 流程执行到事件节点时执行          |
| 流程语义 | 不阻塞、不分支、不改变变量         | 可调用项目定义的业务动作          |
| 定义来源 | 宿主程序自行约定，无需项目资源定义 | 必须符合项目事件资源及参数 Schema |
| 典型用途 | UI、镜头、埋点、宿主自定义扩展     | 设置变量、开始任务、播放演出      |

- `hostEvents` 必须是数组；数组顺序就是广播顺序，编辑器提供上移和下移操作。
- 每一项的 `name` 必须以字母开头，可包含字母、数字、点、横线和下划线；建议使用命名空间格式。
- 每一项的 `payload` 必须是 JSON 对象，只允许 JSON 可序列化数据，不允许脚本、函数或引擎对象引用。
- 广播发生在节点被标记为当前节点之后、节点自身的等待或跳转逻辑之前；同一次节点访问按数组顺序逐条广播。
- 循环或重新进入同一节点时会重新广播完整列表，即语义是“每次节点访问执行一次列表”，不是“整个对话仅一次”。
- 广播为单向通知，宿主返回值不参与对话分支；需要影响分支时应由宿主更新已声明变量，再由条件节点读取。
- 宿主未注册对应消息时应安全忽略并记录可选调试日志，不得中断对话运行。
- 宿主消息按数组顺序同步投递以保证可观察顺序，但运行时忽略监听器返回值或 Promise；单个监听器异常由适配层捕获并记录，后续消息和节点流程继续执行。
- 读取早期的单条 `hostEvent` 字段时，迁移程序将其转换为只包含一项的 `hostEvents` 数组；保存后只写新字段。

### 5.7 多语言文本键

编辑源文件直接保存各语言文本，降低叙事设计师的编辑成本；导出时将文本替换为稳定文本键。文本键不依赖显示名称、可读 Key 或文本内容，默认按实体不可变 UUID 生成：

```text
dialogue.{dialogueId}.{nodeUuid}.text
dialogue.{dialogueId}.{nodeUuid}.choice.{choiceId}.text
character.{characterId}.name
```

节点移动、Key 修改、文本修改和对话改名不会改变文本键。复制节点时会生成新的节点 UUID 或选项 ID，因此也会生成新的文本键，避免两段内容意外共享翻译。

### 6.5 Schema 与迁移

- 项目清单、源文件和运行时导出分别包含 `schemaVersion`。
- 读取旧版本时按顺序执行迁移，例如 `v1 -> v2 -> v3`，不跨版本写临时逻辑。
- 迁移前自动创建备份；迁移成功并由用户保存后才覆盖源文件。
- 遇到高于当前应用支持的版本时以只读方式提示，不尝试降级保存。
- Rust 数据模型作为业务语义的权威实现；JSON Schema、TypeScript 类型与 Zod Schema 通过生成流程或固定契约样例保持一致。
- `schemaVersion` 表示当前文件所属 Schema 的版本，不等同于应用版本；编辑源 Schema 与运行时 Schema 分别维护版本序列，即使序列化字段均命名为 `schemaVersion`，也不能用编辑源版本推断运行时版本，避免编辑源升级迫使宿主同时升级。
- 迁移函数必须是确定性的纯数据转换，并分别记录输入版本、输出版本、修改文件和备份位置；任何文件迁移失败时不替换原项目。
- `hostEvent -> hostEvents[]` 属于读取兼容迁移：旧字段读取后进入内存新模型，只有用户明确保存或执行 `migrate --write` 时才写回。

### 6.6 路径解析与外部修改

路径解析顺序固定为：

1. 读取 `.siming/project.json` 中的项目相对路径。
2. 使用当前打开的项目根目录进行规范化解析。
3. 若本机用户配置存在该 `projectId` 的路径覆盖，则仅在当前设备替换对应用途的最终目录。
4. 校验最终路径、权限、文件类型和路径逃逸。

项目文件加载时记录规范化路径、文件大小、修改时间和内容哈希。保存前再次读取目标文件：

- 哈希未变化：执行原子保存。
- 哈希已变化且当前文档无修改：允许重新加载并刷新基线。
- 哈希已变化且当前文档有修改：进入冲突状态，禁止保存和导出，提供“重新加载”“保留当前版本并另存”“查看差异”。
- 仅修改时间变化但哈希一致：刷新文件元数据，不制造冲突。

文件监听器只负责提示和使缓存失效，不直接覆盖内存模型。目录移动、Git 切换分支和批量外部修改需要防抖合并，避免为同一次操作弹出大量提示。

## 七、状态管理与交互

### 7.1 状态划分

| Store               | 内容                                                                 | 是否持久化到项目               |
| ------------------- | -------------------------------------------------------------------- | ------------------------------ |
| `projectStore`      | 项目信息、语言配置、对话 UUID/Key/路径索引和待应用文件操作           | 是                             |
| `documentStore`     | 当前节点、连线、脏状态                                               | 是                             |
| `resourceStore`     | 角色、变量、业务事件、标签及反向引用索引                             | 是                             |
| `editorStore`       | 选择项、视口、表格分支展开状态、面板开关、目录展开状态和智能分组筛选 | 仅必要的界面偏好写入本机       |
| `sourceEditorStore` | 数据视图草稿、解析状态、诊断和光标位置                               | 否，应用后进入 `documentStore` |
| `historyStore`      | 撤销/重做命令栈                                                      | 否                             |
| `validationStore`   | 最后一次项目诊断、草稿诊断、执行状态和定位信息                       | 否                             |
| `simulationStore`   | 当前节点、临时变量、运行轨迹                                         | 否                             |
| `settingsStore`     | 项目设置草稿、用户设置、主题和路径解析预览                           | 分别写入项目或本机             |

避免建立一个包含全应用数据的巨型 Store。领域数据修改必须通过命令或明确 action 完成，React 组件不直接修改节点对象。

三视图共享 `documentStore` 中的同一规范化模型。画布坐标属于文档数据，选择状态、缩放比例、表格展开和数据编辑器光标属于编辑器状态；运行时预览由最后有效文档派生并缓存，不能反向修改源模型。

### 7.2 撤销与重做

- 使用命令模式记录可逆操作，不为鼠标拖动的每一帧创建历史。
- 连续文本输入在短时间内合并为一次操作，失焦后结束合并。
- 保存不会清空历史；通过保存时的历史位置判断文档是否有未保存修改。
- 数据视图中一次“应用修改”作为一条原子历史记录，撤销后恢复应用前的完整文档。
- 命令按 `document`、`resource`、`workspace` 标记作用域。目录移动、文件重命名等工作区命令记录源路径、目标路径和项目索引逆操作，资源重命名记录全部引用修改，确保一次撤销恢复完整一致状态。
- 未保存的目录和文件操作保存在工作区变更集中，目录树展示“预期磁盘状态”并标记待保存；保存时由存储层将文件移动、内容写入和项目索引替换作为一个带日志的事务执行，避免文件已移动但索引未更新。
- 工作区保存事务成功后不清空撤销栈；撤销已保存的文件操作会产生一个新的反向工作区变更，需再次保存才落盘。
- 切换项目时清空历史；切换对话时保留项目级历史游标，并按命令作用域恢复对应文档，不能让资源或目录命令因切换对话而丢失。

### 7.3 保存与恢复

- 用户保存时执行：确认不存在未应用的数据草稿 → 前端整理文档及工作区变更集 → IPC → 共享核心校验与序列化 → 存储层写入临时文件并执行带日志的路径移动 → 刷盘 → 原子替换项目索引和内容文件 → 清理事务日志。
- 自动恢复快照写入应用数据目录，不污染项目仓库。
- 正常保存后清理对应快照；异常退出后再次打开应用时提示恢复。
- 检测源文件在应用外被修改的情况，提示重新加载、另存或保留当前版本，不静默覆盖。
- 关闭窗口、切换项目或退出应用时，对未保存文档进行统一拦截提示。
- 快照包含项目 ID、源文件相对路径、基线内容哈希、最后有效文档、可选数据草稿、生成时间和应用版本；恢复前先验证项目 ID 与 Schema 兼容性。
- 自动恢复快照采用节流写入，只有存在脏文档或草稿时生成；设置中的间隔表示快照频率，不是覆盖项目文件的频率。
- “保留当前版本”不会直接覆盖外部文件，而是继续保持冲突状态，直到用户选择另存或明确完成差异处理。
- 启动时若检测到未清理的保存事务日志，存储层根据事务阶段完成提交或回滚，再向用户报告恢复结果；不得让 UI 直接猜测磁盘状态。

## 八、前后端接口

MVP 建议提供以下 Tauri Command：

| 命令                    | 用途                       | 关键约束                              |
| ----------------------- | -------------------------- | ------------------------------------- |
| `create_project`        | 创建项目目录和默认文件     | 目标目录必须为空或不存在              |
| `open_project`          | 读取项目清单               | 返回结构化错误，不直接弹 UI           |

| `validate_source_draft` | 校验数据视图草稿           | 返回解析、Schema 和业务诊断，不写文件 |

| `export_project`        | 编译并导出运行时数据       | 有错误时拒绝导出，使用共享存储层写入  |

| `list_recent_projects`  | 读取最近项目               | 路径保存在应用配置目录                |

| `read_user_settings`    | 读取本机用户设置           | 未知主题值回退为 `dark`               |

| `show_in_folder`        | 在系统文件管理器中定位文件 | 仅允许已打开项目内路径                |

统一错误结构：

```ts
type AppError = {
  code: string;
  message: string;
  recoverable: boolean;
  details?: Record<string, unknown>;
};
```

前端根据 `code` 和 `recoverable` 决定交互，`message` 用于日志或兜底提示，避免依赖错误文案判断类型。批量操作返回整体结果及逐文件错误，不使用“部分成功但仍返回成功”的模糊语义。

CLI 不经过 Tauri IPC，而是直接调用相同的 `siming-core` 和 `siming-storage` Rust crate。

## 九、安全与可靠性

- Tauri 权限按最小范围配置，只开启项目需要的文件和窗口能力。
- 所有项目相对路径在 Rust 侧规范化，并确认最终路径仍位于项目根目录内。
- CLI 对项目内部引用使用与桌面端相同的规范化与路径逃逸检查；导出只写入用户显式指定的目标目录。
- 不执行项目文件中的脚本、Shell 命令或动态加载的本地代码。
- 导入 JSON 时限制单文件大小、节点数量和嵌套深度，防止异常文件耗尽资源。
- 保存、迁移和导出使用可诊断错误，不因单个损坏对话导致整个项目无法打开。
- 日志默认不记录完整对话正文和用户本机敏感路径。

## 十、性能目标

MVP 以普通开发设备为基准，目标如下：

| 场景                           | 目标                         |
| ------------------------------ | ---------------------------- |
| 冷启动到可操作                 | 3 秒以内                     |
| 打开 1,000 节点的单个对话      | 2 秒以内                     |
| 画布拖拽和缩放                 | 主观无明显卡顿，目标 60 FPS  |
| 普通编辑操作反馈               | 100 毫秒以内                 |
| 1,000 节点对话完整校验         | 500 毫秒以内                 |
| 打开并格式化 1,000 节点源 JSON | 1 秒以内                     |
| CLI 校验 10,000 节点项目       | 5 秒以内                     |
| 项目保存                       | 1 秒以内，不阻塞界面持续响应 |

实现策略：

- 只渲染可视区域内的复杂节点内容，避免无关组件重复更新。
- Zustand selector 精确订阅节点局部状态。
- 拖动过程中只更新必要位置数据，结束后再写入撤销历史。
- 校验、布局等重计算任务按需防抖；完整校验通过异步 IPC 在 Rust 后台任务中执行，避免阻塞界面线程。
- 首期不为性能提前引入数据库，以真实压测结果决定是否调整存储方式。

可用性与可访问性约束：

- 主导航、目录、三视图切换、属性表单、保存、校验和模拟器关键操作必须可通过键盘访问，并具有可见焦点状态。
- 图标按钮必须提供可读名称和悬浮提示；颜色不得作为错误级别、选中状态或分支语义的唯一表达。
- `Dark` 与 `Light` 主题的正文、控件、边框、焦点和诊断状态使用统一语义令牌，并在持续集成中执行基础对比度检查。
- 大型目录、搜索结果、资源列表和表格采用虚拟化或分段渲染；画布节点编辑器只挂载可视范围内的高成本内容。
- 尊重系统“减少动态效果”偏好；主题切换和面板动画不得阻塞输入，也不能让画布丢失选择与视口。

## 十一、测试策略

### 11.1 单元测试

- 节点和连线规则。
- 条件表达式求值与类型检查。
- 多语言回退、缺失翻译检查和稳定文本键生成。
- 源文件 Schema 校验与版本迁移。
- 数据草稿解析、格式化、应用及编辑模型往返转换。
- 源模型到运行时模型的编译结果。
- 角色、变量、事件和标签的引用统计、重命名传播及删除保护。
- CLI 参数解析、诊断序列化和退出码映射。
- 撤销/重做命令及脏状态判断。
- 表格稳定遍历、汇合引用行和循环回跳标记。
- 主题枚举、用户配置默认值、未知配置回退和项目/用户路径覆盖优先级。
- 确定性序列化、业务顺序数组保持和跨平台换行。

### 11.2 集成测试

- 前端调用 IPC 后正确处理成功和失败结果。
- 新建、读取、原子保存及外部修改冲突。
- 含目录移动、资源修改和多个对话写入的工作区事务提交、故障回滚及启动恢复。
- 损坏文件、未知版本和缺失引用的错误恢复。
- 自动恢复快照的生成、恢复和清理。
- 文件监听、内容哈希冲突判断及“重新加载/另存/查看差异”状态转换。
- 画布编辑后数据视图同步更新，数据修改应用后画布得到等价结果。
- 无效 JSON、Schema 错误和未应用草稿不会覆盖最后有效文档。
- 项目设置只保存相对路径，项目外绝对导出目录只保存为本机覆盖。
- Dark/Light 切换立即覆盖所有主要界面区域，重开恢复且重置回到 Dark。
- 对同一项目分别通过 Tauri Command 和 CLI 校验、导出，结果必须完全一致。

### 11.3 端到端测试

至少覆盖以下主路径：

1. 新建项目并创建一段线性对话。
2. 添加选项与条件分支并通过校验。
3. 保存、关闭、重新打开后内容和布局一致。
4. 在表格视图确认选项、条件、汇合和循环路径的顺序与标识，并点击行验证画布选择和属性面板同步。
5. 在数据视图修改对白和节点坐标，应用后确认画布内容、表格内容及位置同步变化。
6. 输入无效 JSON，确认错误定位、切换拦截和原有效文档均符合预期。
7. 新建并编辑角色、变量、事件和标签，在内容属性中选择资源并反向查看引用位置。
8. 尝试删除被引用资源或修改变量类型，确认保护和错误定位行为。
9. 在模拟器中修改变量并走到不同分支。
10. 为不同类型节点配置多条宿主消息并调整顺序，确认每次进入节点都按列表顺序逐条广播，且与业务事件执行器相互隔离。
11. 切换预览语言，确认完整翻译和默认语言回退均符合预期。
12. 导出对话结构与各语言资源，并与固定运行时样例比对。
13. 制造未保存修改后退出，确认拦截与恢复行为。
14. 分别运行 CLI 的校验、导出、迁移检查和信息查询，核对 stdout、stderr 与退出码。
15. 切换 Dark/Light、重新启动应用和恢复默认设置，确认主题持久化边界。
16. 从项目外修改已打开文件，确认冲突解决前不能保存或导出。
17. 打开导出格式菜单，确认 JSON 可用，XML 和二进制明确标记为后续版本且不会产生伪导出文件。

### 11.4 跨平台验证

- CI 至少执行 TypeScript 检查、Lint、单元测试和 Rust 测试。
- Windows、macOS、Linux 分别执行桌面应用和 CLI 构建验证。
- CI 使用构建出的 `siming` 二进制运行固定项目，验证其不依赖桌面环境。
- 每个正式版本在三平台进行一次手工冒烟测试，重点检查文件路径、快捷键和窗口行为。
- 使用同一固定项目比较三平台导出文件哈希；除显式允许的安装包差异外，运行时 JSON 和语言资源必须字节一致。
- Windows 额外覆盖文件占用与替换失败，macOS 覆盖应用沙箱/权限提示，Linux 覆盖常见桌面环境的文件选择与配置目录解析。

## 十二、开发阶段

### 阶段 0：工程基线

- 初始化 Rust Workspace、`siming-core`、`siming-storage`、CLI、Tauri、React、TypeScript、Tailwind CSS 和测试工具。
- 建立代码检查、格式化、CI 和三平台构建流程。
- 定义源文件 Schema、示例数据和架构决策记录。

**完成标准：** 三个平台可以构建并打开空白应用，也能运行 `siming --version`；前后端 IPC 和共享核心测试通过。

### 阶段 1：可编辑闭环

- 完成项目新建、打开和保存。
- 完成真实对话目录、文件操作、智能分组、项目搜索、基础节点、连线、属性编辑和撤销/重做。
- 完成角色、变量、事件、标签四个资源编辑器及引用查看和删除保护。
- 完成画布/表格/数据三视图、分支顺序阅读、源 JSON 草稿校验、格式化与应用修改。
- 完成默认语言、支持语言配置和多语言文本字段编辑。
- 完成项目/用户设置作用域、相对路径解析、Dark/Light 主题、脏状态、退出拦截和基础错误提示。

**完成标准：** 用户能通过画布和源 JSON 编辑一段含分支及两种语言文本的对话，在表格中按路径顺序阅读并识别分支与汇合；三个视图结果一致，保存后重新打开内容不变。

### 阶段 2：可验证闭环

- 完成全量校验、问题定位和不可达节点分析。
- 完成条件表达式编辑、变量定义和模拟运行器。
- 完成语言切换预览、默认语言回退和翻译完成度检查。
- 完成运行轨迹、业务事件测试执行器、多宿主消息顺序日志与无限循环保护。

**完成标准：** 用户不启动游戏即可验证同一对话在不同变量和预览语言下的分支及文本结果。

### 阶段 3：可交付闭环

- 完成运行时结构、分语言资源 JSON 编译导出、Schema 版本迁移和恢复快照。
- 完成确定性 JSON 导出，以及 `validate`、`export`、`migrate`、`info` 子命令、PRD 约定参数和稳定退出码。
- 完成性能优化、端到端测试、三平台桌面安装包和 CLI 压缩包。
- 提供运行时格式说明和最小接入示例。

**完成标准：** 导出数据可由独立示例程序读取、切换语言并完整走通对话；三平台桌面安装包和 CLI 均通过冒烟测试。

## 十三、MVP 验收标准

当以下条件全部满足时，MVP 可视为完成：

- 能创建并管理包含多份对话的本地项目。
- 设置中心能明确区分项目设置与用户设置；项目设置写入项目配置，用户设置只保存在本机。
- 对话目录和导出目录支持项目相对路径，移动或由其他成员检出项目后能解析到正确位置，且项目配置中不出现成员电脑的项目根绝对路径。
- 项目外绝对导出目录只作为本机覆盖保存，不进入 `.siming/project.json`；删除覆盖后恢复共享相对路径。
- 非法路径、不可写目录和逃逸项目根目录的相对路径会阻止应用设置并给出明确原因。
- `Dark`、`Light` 可立即切换全部主要界面，刷新或重开后恢复上次选择，重置用户设置后回到 `Dark`，且不改变项目文件和导出结果。
- 对话目录树与磁盘相对路径一致；新建、重命名、展开、收起和拖拽移动目录后，项目清单路径正确更新。
- 未保存目录移动可撤销；保存事务中断后重启不会出现文件路径与项目索引各成功一半的状态。
- 移动或重命名对话文件不会改变对话 UUID、文本键和跨文件引用；重复 UUID、Key 或路径会阻止保存。
- 最近编辑、存在错误、翻译未完成等智能分组能正确筛选对话，且不会改变真实目录结构。
- 六类节点均可通过画布创建、编辑、连接、复制和删除。
- 六类节点均可独立配置多条宿主消息；新增、删除和排序行为正确，每次进入节点时按数组顺序逐条广播，消息名和 JSON 参数能原样导出，未注册监听器不会阻断流程。
- 宿主消息与业务事件节点使用不同字段、校验规则和运行时回调，不会被错误地当作业务事件执行。
- 角色、变量、事件和标签均有可搜索、可新增的独立列表及对应属性编辑界面。
- 能从资源查看全部引用位置；删除被引用资源时必须阻止操作并定位引用。
- 变量类型、默认值和事件参数 Schema 能正确校验，并同步反映到节点属性选择器。
- 能查看并编辑当前对话的真实源 JSON，格式化、Schema 校验和错误定位行为正确。
- 数据视图修改只有在明确应用且通过校验后才同步到画布；无效或未应用草稿不会污染保存内容。
- 表格视图按拓扑顺序展示全部节点；选项、条件、汇合与循环路径标识明确，点击行可与画布选择和属性面板联动。
- 未选择节点时属性面板展示当前对话的描述、标签等文件级属性；选择节点和点击画布空白处时能在文件属性与节点属性之间正确切换。
- 画布、表格与数据视图往返切换后，节点、连线、坐标、多语言文本、UUID 和 Key 保持一致。
- 连续新建或复制节点不会产生重复 UUID；重复 UUID、重复 Key、非法 UUID 和悬空引用均会阻止应用源数据并定位错误。
- 普通节点只导出单一 `next`；选项目标写入各选项的 `next`；条件目标写入具名 `branches.true/false`，运行时结构中不存在无语义的 `next` 数组。
- 能配置默认语言和至少两种支持语言，并编辑对话、选项和角色名称的多语言文本。
- 撤销、重做和未保存状态在节点、连线与属性操作中行为一致。
- 保存失败不会破坏原文件，异常退出后可提示恢复未保存内容。
- 校验能识别结构错误、无效引用和不可达节点，并能定位问题。
- 模拟器能根据变量和玩家选项正确推进，且不会因死循环锁死界面。
- 模拟器能切换预览语言，缺失翻译时按照固定规则回退并清楚标记。
- 导出文件不包含画布坐标等编辑器信息，对话结构和各语言资源均通过 JSON Schema 或等价校验。
- 文本键在修改文本、移动节点和重命名对话后保持稳定，各语言资源使用同一组文本键。
- 同一输入产生稳定的导出结果，便于版本控制和自动化测试。
- 导出主按钮使用最近选择的格式；JSON、XML 和二进制均生成经过校验的正式产物。
- CLI 能无界面执行校验、导出、迁移检查和项目信息查询，并遵守文档约定的 JSON 输出及退出码。
- 同一项目通过桌面端和 CLI 得到的诊断及导出内容一致。
- Windows、macOS、Linux 均能安装、启动、打开项目、保存和导出，并能单独运行 CLI。
- 1,000 节点基准样例达到本方案的主要性能目标。

## 十四、主要风险与应对

| 风险                             | 影响                               | 应对措施                                                           |
| -------------------------------- | ---------------------------------- | ------------------------------------------------------------------ |
| 大型对话图渲染卡顿               | 编辑体验下降                       | 可视区域优化、精确订阅、基准压测，必要时拆分子图                   |
| 源文件格式频繁变化               | 项目文件无法兼容                   | Schema 版本、顺序迁移、备份和固定样例测试                          |
| 编辑状态与文件内容不一致         | 数据丢失或误覆盖                   | 原子保存、脏状态、恢复快照和外部修改检测                           |
| 原始数据编辑绕过画布约束         | 产生无法打开或无法导出的项目       | 独立草稿、Schema 与完整业务校验、显式应用和最后有效文档回退        |
| 画布、表格与数据视图状态不一致   | 用户误读分支或修改丢失             | 单一文档模型、共享选择状态、视图切换拦截、原子应用和三视图往返测试 |
| 资源变更破坏节点引用             | 对话出现无效角色、变量或事件       | 稳定 ID、引用索引、受控重命名、删除保护和全项目校验                |
| 条件系统过度复杂                 | 各引擎实现不一致                   | MVP 限制类型和运算符，以结构化 AST 作为唯一语义                    |
| 多语言文本键随编辑变化           | 已接入翻译或配音失效               | 文本键只基于不可变 UUID 生成，并添加快照测试                       |
| 手工节点标识重复或重命名破坏连线 | 节点覆盖、跳转错误或数据无法加载   | UUID 自动生成且不可变，Key 单文件唯一，保存前校验重复和悬空引用    |
| 部分语言翻译不完整               | 玩家看到空文本                     | 默认语言必填、导出前统计缺失项、运行时执行固定回退                 |
| 通用格式承载过多引擎特性         | 协议失去稳定性                     | 核心字段保持通用，引擎特有能力通过命名空间事件扩展                 |
| 跨平台文件行为不同               | 某些平台无法保存或打开             | 统一路径处理、三平台 CI 构建和发布前冒烟测试                       |
| GUI 与 CLI 行为不一致            | 本地通过但 CI 失败，或导出内容不同 | 共享 Rust 核心与存储层，并对两种入口执行契约对照测试               |
| CLI 输出混入日志                 | CI 无法稳定解析 JSON               | JSON 只写 stdout，日志写 stderr，并使用快照测试固定格式            |
| Tauri 与前端依赖升级不兼容       | 构建或运行受阻                     | 固定 lockfile，小步升级，升级前运行完整测试矩阵                    |

## 十五、后续扩展方向

MVP 稳定后可按实际项目需求评估：

- 为 Unity、Unreal 等宿主提供读取目录分片和三种正式格式的 SDK 与导入器。
- Unity、Unreal 或其他引擎的运行时 SDK 与导入器。
- CSV/XLIFF 导入导出、翻译平台同步、术语库和翻译审核状态。
- 应用界面本身的多语言切换。
- 角色立绘、语音和演出资源的预览引用。
- 子对话、函数式复用节点和跨对话跳转。
- 自定义节点与事件定义插件，但保持受控权限与数据 Schema。
- Git 差异可视化、冲突辅助处理和团队审核流程。
- 只读 Web 预览或可分享的剧情走查包。

## 十六、需求—技术追踪

| PRD 模块       | 核心技术落点                                  | 关键持久化/契约                         | MVP 验证入口                       |
| -------------- | --------------------------------------------- | --------------------------------------- | ---------------------------------- |
| 项目管理       | `siming-storage` 原子写入、版本检测、恢复快照 | `.siming/project.json`、内容哈希        | 新建、移动项目、写入失败、异常恢复 |
| 目录与文件     | 相对路径索引、目录扫描、拖拽移动事务          | 对话索引 `id/key/path`                  | 拖拽、重命名、强引用删除保护       |
| 项目搜索       | 全项目只读索引、稳定定位信息                  | UUID、相对路径、`fieldPath`             | 搜索文本/ID并跳转                  |
| 四类资源       | 资源仓储与反向引用索引                        | `definitions/*.json`                    | 重命名传播、删除保护               |
| 项目/用户设置  | 双作用域配置解析                              | 项目相对路径、本机绝对覆盖              | 跨路径打开、主题持久化             |
| 画布/表格/数据 | 单一 `documentStore`、派生视图、草稿隔离      | 源模型 + 非持久化视图状态               | 三视图往返、草稿拦截               |
| 节点与分支     | UUID、具名端口、结构化条件 AST                | `choices[].next`、`branches.true/false` | 固定运行时样例                     |
| 多宿主消息     | 有序数组和独立回调                            | `hostEvents[]`                          | 顺序日志、未知消息继续             |
| 校验中心       | `siming-core` 分阶段诊断                      | 稳定 `Diagnostic.code`                  | GUI/CLI 结果对照                   |
| 模拟运行       | 纯内存运行上下文和步数保护                    | 不回写项目变量                          | 选择、条件、循环、事件日志         |
| 内容多语言     | `LocalizedText`、稳定文本键、固定回退         | 分语言 JSON                             | 缺失统计、回退与导出               |
| 导出           | 规范运行时模型、确定性 JSON 序列化            | 结构 JSON + locale JSON                 | 多次导出哈希一致                   |
| CLI            | Clap 适配层复用核心与存储                     | stdout JSON、stderr 日志、退出码        | 四个子命令契约测试                 |
| 跨平台         | Tauri 平台适配与统一路径层                    | UTF-8、项目路径使用 `/`                 | 三平台构建、冒烟、哈希对照         |

实施过程中若 PRD 交互稿、本文数据示例与 Schema 文件出现冲突，处理顺序为：

1. 先确认 PRD 中的产品语义和版本边界。
2. 再以 `schemas/` 中发布的版本化 Schema 固定机器契约。
3. 同步更新本文示例、共享 fixtures、TypeScript 类型和 Rust 模型。
4. 通过 GUI/CLI 契约测试后再允许合并，禁止只修改某一端以“兼容”冲突。
