# Siming 对话编辑器技术方案

## 一、项目概述

Siming 是一个脱离游戏引擎运行的通用剧情对话编辑器，面向叙事设计师和游戏开发者，用于可视化配置带有分支与条件判断的剧情对话。

编辑器负责对话内容的创建、组织、校验、预览和导出；游戏侧负责读取导出数据，并自行实现 UI、角色表现、音频播放及具体业务逻辑。

### 1.1 核心诉求

- 通过节点画布编辑对话树，支持拖拽、连线、缩放和布局。
- 支持普通对话、玩家选项、条件分支和剧情结束等基本流程。
- 使用与游戏引擎无关的 JSON 数据格式，方便 Unity、Unreal 或自研引擎接入。
- 在同一份对话中维护多语言文本，并按语言预览、校验和导出。
- 内置模拟运行功能，无需启动游戏即可检查分支、条件和对话顺序。
- 提供无界面的命令行模式，支持在 CI 和批处理流程中校验、导出和检查项目。
- 支持 Windows、macOS 和 Linux，项目文件可由 Git 等版本控制工具管理。

### 1.2 设计原则

- **内容与表现分离**：数据描述“说什么、何时分支、触发什么”，不约束游戏内 UI 和演出方式。
- **编辑数据与运行数据分离**：画布坐标等编辑器信息不进入最终运行时数据。
- **显式且可校验**：节点、连线、条件和变量均有明确结构，尽量在导出前发现错误。
- **稳定优先**：文件格式带版本号，节点使用稳定 ID，避免调整布局造成无意义的数据变更。
- **渐进扩展**：先完成包含基础多语言能力的单机 MVP，再扩展翻译平台协作、多人协作和引擎插件。

### 1.3 MVP 范围

MVP 包含以下能力：

1. 创建、打开、保存对话项目。
2. 创建和管理多个对话文件。
3. 编辑开始、对话、选项、条件、事件和结束节点。
4. 创建、删除和修改节点之间的连线。
5. 配置角色、变量、条件表达式和事件参数。
6. 撤销、重做、复制、粘贴、搜索和基础快捷键。
7. 校验对话图并定位错误节点。
8. 从任意入口模拟运行对话，并临时修改变量观察分支结果。
9. 配置项目默认语言和支持语言，在同一节点中编辑、切换和预览多语言文本。
10. 校验缺失翻译，并按稳定文本键导出各语言资源。
11. 导出与引擎无关的运行时 JSON。
12. 通过命令行执行项目校验、导出、迁移检查和项目信息查询。
13. 构建 Windows、macOS 和 Linux 桌面应用及命令行程序。

以下能力暂不纳入 MVP：

- 多人实时协作、云同步和账号系统。
- 游戏内 UI、立绘、动画、Timeline 或音频播放。
- 完整脚本语言及任意代码执行。
- Excel、CSV、XLIFF、Ink、Yarn Spinner 等第三方格式的双向转换。
- Unity、Unreal 的官方运行时插件。
- 翻译平台同步、机器翻译、术语库、翻译审核和配音资产管理。
- 在终端中交互式创建或编辑节点图。

## 三、总体架构

应用采用“React 桌面界面 + Tauri 桌面适配层 + Rust 共享核心 + Rust CLI + 本地项目文件”的结构。桌面端和命令行端共用同一套校验、迁移与导出实现。

```text
┌────────────────────────────┐   ┌──────────────────────────┐
│ React 桌面界面             │   │ siming CLI               │
│ 画布 │ 属性 │ 历史 │ 模拟器 │   │ validate │ export │ info │
└─────────────┬──────────────┘   └────────────┬─────────────┘
              │ Tauri IPC                     │ CLI 适配层
┌─────────────▼────────────────────────────────▼─────────────┐
│ Rust 共享核心业务层（siming-core）                         │
│ 数据模型 │ Schema │ 完整校验 │ 条件求值 │ 编译导出 │ 迁移   │
├────────────────────────────────────────────────────────────┤
│ 共享存储层（siming-storage）                               │
│ 项目读取 │ 路径校验 │ 原子写入 │ 备份                       │
├────────────────────────────────────────────────────────────┤
│ 本地文件系统                                               │
│ 项目配置 │ 对话源文件 │ 角色/变量定义 │ 导出文件             │
└────────────────────────────────────────────────────────────┘
```

### 3.1 前端职责

- 渲染应用界面、节点画布和属性表单。
- 维护当前文档、选择状态、视口状态和撤销历史。
- 执行不改变业务语义的即时交互约束，例如端口是否已连接和必填字段提示。
- 通过 Tauri IPC 调用权威校验、条件求值、编译导出、迁移和文件能力。

### 3.2 Rust 共享核心职责

- 定义项目、节点、条件、多语言文本和运行时导出的权威数据模型。
- 实现完整校验、条件求值、文本回退、稳定文本键和运行时编译。
- 实现 Schema 版本检测与纯数据迁移。
- 不依赖窗口、终端和具体文件对话框，保证桌面端与 CLI 结果一致。

### 3.3 桌面与存储层职责

- 打开项目目录、读取源文件和列出项目资源。
- 使用临时文件加替换方式原子保存，避免写入中断损坏源文件。
- 提供文件选择、最近项目和应用配置等桌面能力。
- 限制文件访问范围，不向前端暴露任意命令执行能力。

### 3.4 CLI 职责

- 解析命令行参数，读取项目并调用共享核心。
- 将命令结果按所选格式写到标准输出流，将运行日志和非结果错误写到标准错误流。
- 使用稳定退出码表达成功、校验失败、输入错误和内部错误。
- 默认无交互运行；会改写文件的操作必须显式传入写入参数。

### 3.5 边界约束

- 权威业务规则只在 `siming-core` 实现，React 和 CLI 不各自复制一套校验或导出规则。
- React 可实现即时交互提示，但最终结果必须以共享核心返回值为准。
- TypeScript 类型、JSON Schema 与 Rust 数据模型通过代码生成或契约测试保持一致。
- 所有 IPC 命令使用明确的输入输出类型，并在前后端边界执行数据校验。

### 3.6 建议代码组织

```text
siming/
├── apps/
│   └── desktop/              # React 前端与 Tauri 桌面适配层
├── crates/
│   ├── siming-core/          # 数据模型、校验、求值、导出与迁移
│   ├── siming-storage/       # 项目读取、路径检查、原子写入与备份
│   └── siming-cli/           # siming 命令行程序
├── schemas/                  # 对外发布的 JSON Schema
├── fixtures/                 # GUI、CLI 和迁移共用的契约测试项目
└── docs/
```

## 四、功能模块

### 4.1 项目管理

- 新建项目时生成项目清单、默认角色和第一份对话文件。
- 打开项目时先校验格式版本，再加载项目索引和目标对话。
- 记录最近打开的项目，但不将本机绝对路径写入项目源文件。
- 项目内文件使用相对路径，保证跨设备和版本控制可用。

### 4.2 对话文件管理

- 一个项目可包含多份对话，每份对话拥有稳定 ID、显示名称和入口节点。
- 支持创建、重命名、复制和删除对话；删除前明确提示该操作影响的文件。
- 对话列表提供名称和 ID 搜索，并显示未保存、警告和错误状态。

### 4.3 节点画布

- 支持框选、多选、拖拽、连线、缩放、平移、适应视图和小地图。
- 支持复制粘贴节点；粘贴时为节点和内部连线生成新 ID。
- 节点删除、移动、字段修改和连线操作全部进入统一撤销/重做历史。
- 画布只负责交互，节点结构和连线合法性由共享核心业务层判断。

### 4.4 属性编辑器

- 根据节点类型展示对应字段，并对必填项、类型和引用进行即时校验。
- 角色、变量和事件通过下拉选择已有定义，避免自由文本造成拼写差异。
- 对高级参数保留 JSON 值类型，但不允许执行任意 JavaScript 或系统命令。

### 4.5 校验中心

校验分为错误和警告：错误会阻止导出，警告允许导出但需要显式展示。

**错误示例：**

- 缺少唯一开始节点或存在多个开始节点。
- 必填文本为空、节点 ID 重复或引用不存在。
- 必须有出口的节点没有有效连线。
- 同一选项存在多个无法确定优先级的出口。
- 条件表达式类型不匹配或引用未定义变量。
- 默认语言的必填文本缺失。

**警告示例：**

- 存在从入口不可到达的节点。
- 存在没有退出路径的循环。
- 角色、事件或变量已定义但未使用。
- 非默认语言存在缺失翻译，运行时将回退到默认语言。
- 对话文本可能超过建议长度。

点击校验项后，画布应定位并选中对应节点或连线。

### 4.6 模拟运行器

- 从入口节点或当前选中节点开始运行。
- 展示当前说话人、对话内容、可选项和已执行事件。
- 可切换预览语言；发生默认语言回退时标记对应文本。
- 提供变量面板，可在测试期间修改变量并重新计算条件分支。
- 记录本次运行经过的节点和条件结果，便于定位错误。
- 模拟器只修改内存中的运行上下文，不回写项目变量默认值。
- 设置最大连续步数，检测没有等待用户输入的无限循环。

### 4.7 多语言编辑

- 项目必须设置一个默认语言，并可配置多个支持语言；语言代码使用 BCP 47 形式，例如 `zh-CN`、`en-US`。
- 对话正文、选项文本和角色显示名使用统一的多语言文本结构。
- 属性面板固定显示默认语言，并允许切换或并排编辑其他语言。
- 画布和搜索默认使用当前预览语言；缺失时显示默认语言并附加回退标记。
- 默认语言文本为必填；其他语言允许暂时缺失，但必须进入校验结果和翻译完成度统计。
- 删除语言配置前提示该语言已有文本数量，确认后才移除对应内容。
- MVP 的多语言范围是项目内容，不要求 Siming 应用界面本身支持多语言切换。

多语言字段统一表示为：

```ts
type LocalizedText = Record<string, string>;

const example: LocalizedText = {
  "zh-CN": "故事从这里开始。",
  "en-US": "The story begins here."
};
```

运行时回退规则固定为：请求语言文本 → 项目默认语言文本 → 返回缺失文本错误。MVP 不实现 `zh-Hant-TW → zh-Hant → zh` 等语言层级推导，避免编辑器与各引擎产生不同结果。

### 4.8 导出器

导出过程分为五步：

1. 校验项目和目标对话。
2. 将编辑器模型编译为语言无关的对话结构。
3. 使用稳定文本键提取各语言文本资源。
4. 移除画布坐标、折叠状态等编辑器专用字段。
5. 按稳定顺序输出运行时结构和语言资源 JSON，降低版本控制中的无意义差异。

导出器首期仅输出 JSON，包括一份对话结构和每种语言一份文本资源。后续引擎适配器应消费同一运行时模型，不直接读取编辑器源文件。

### 4.9 命令行模式

CLI 可执行文件名为 `siming`，默认使用当前目录作为项目路径，也可显式传入路径。MVP 提供以下子命令：

```bash
# 校验项目；默认输出适合阅读的诊断信息
siming validate ./example-project

# 为 CI 输出结构化结果，并将警告视为失败
siming validate ./example-project --format json --warnings-as-errors

# 导出全部对话及语言资源
siming export ./example-project --output ./build/dialogues

# 仅检查项目是否需要迁移，不改写文件
siming migrate ./example-project --check

# 执行迁移；写入前自动备份
siming migrate ./example-project --write

# 查看项目版本、语言、对话数量及校验摘要
siming info ./example-project --format json
```

CLI 约定：

- `validate` 和 `info` 只读；`export` 只写入指定导出目录。
- `migrate` 默认只报告状态，只有提供 `--write` 才能改写源项目。
- `--format text` 面向用户阅读，`--format json` 面向 CI 和其他工具消费。
- JSON 模式下，标准输出只包含一个完整 JSON 文档；日志和诊断摘要写入标准错误流。
- 诊断结果包含稳定的 `code`、`severity`、文件相对路径、节点 ID 和消息，方便 CI 精确定位。
- CLI 和桌面端使用相同配置、Schema、校验、迁移和导出代码。

退出码约定：

| 退出码 | 含义 |
| --- | --- |
| `0` | 命令成功，且不存在会导致失败的诊断 |
| `1` | 项目校验失败，或启用 `--warnings-as-errors` 后存在警告 |
| `2` | 参数错误、项目无法读取、版本不受支持或输出路径无效 |
| `3` | 未预期的内部错误 |

桌面安装包和 CLI 作为两个产物发布。CLI 不依赖桌面窗口或前端资源，可单独用于构建服务器；安装脚本或包管理器集成不属于 MVP，首期提供压缩包和校验值。

## 五、节点与连线设计

### 5.1 MVP 节点类型

| 类型 | 用途 | 入口 | 出口规则 |
| --- | --- | --- | --- |
| `start` | 对话入口 | 无 | 必须且只能有 1 个 |
| `dialogue` | 角色对白或旁白 | 1 个或多个 | 必须且只能有 1 个 |
| `choice` | 玩家可选分支 | 1 个或多个 | 每个选项对应 1 个出口 |
| `condition` | 按变量判断走向 | 1 个或多个 | `true`、`false` 各 1 个 |
| `event` | 通知游戏侧执行事件 | 1 个或多个 | 必须且只能有 1 个 |
| `end` | 结束当前对话 | 1 个或多个 | 无 |

### 5.2 连线规则

- 连线以 `sourceNodeId`、`sourcePort`、`targetNodeId` 和 `targetPort` 表示。
- 节点端口决定语义，例如条件节点固定使用 `true` 和 `false` 出口。
- 默认禁止无意义的自连接；循环必须经过明确的多个节点路径。
- 新建连线时即时检查端口数量、类型和重复连接。
- 删除带引用的端口或选项时，同时删除对应连线并进入同一撤销操作。

### 5.3 条件表达式

MVP 不引入可执行脚本，使用结构化条件表达式：

```json
{
  "all": [
    { "variable": "favor", "operator": ">=", "value": 10 },
    { "variable": "hasKey", "operator": "==", "value": true }
  ]
}
```

首期支持：

- 变量类型：`boolean`、`number`、`string`。
- 比较运算：`==`、`!=`、`>`、`>=`、`<`、`<=`。
- 逻辑组合：`all`、`any`、`not`。
- 字符串只允许 `==` 和 `!=`；大小比较只用于数字。

结构化表达式便于表单编辑、静态校验，并可由不同游戏引擎一致实现。

### 5.4 事件设计

事件用于向游戏侧发送声明式指令，例如设置变量、开始任务或播放演出：

```json
{
  "event": "quest.start",
  "params": {
    "questId": "find_the_key"
  }
}
```

编辑器只校验事件名称和参数是否符合项目内的事件定义，不执行游戏逻辑。MVP 内置 `variable.set`、`variable.add`，其他事件由项目自行定义。

### 5.5 多语言文本键

编辑源文件直接保存各语言文本，降低叙事设计师的编辑成本；导出时将文本替换为稳定文本键。文本键不依赖显示名称或文本内容，默认按实体稳定 ID 生成：

```text
dialogue.{dialogueId}.{nodeId}.text
dialogue.{dialogueId}.{nodeId}.choice.{choiceId}.text
character.{characterId}.name
```

节点移动、文本修改和对话改名不会改变文本键。复制节点时会生成新的节点或选项 ID，因此也会生成新的文本键，避免两段内容意外共享翻译。

## 六、数据与文件设计

### 6.1 项目目录


运行时结构使用按 ID 索引的对象，方便引擎快速查找；文本资源按语言拆分，方便游戏按需加载；编辑器源文件保留数组、坐标和多语言原文，方便编辑与序列化。

### 6.5 Schema 与迁移

- 项目清单、源文件和运行时导出分别包含 `schemaVersion`。
- 读取旧版本时按顺序执行迁移，例如 `v1 -> v2 -> v3`，不跨版本写临时逻辑。
- 迁移前自动创建备份；迁移成功并由用户保存后才覆盖源文件。
- 遇到高于当前应用支持的版本时以只读方式提示，不尝试降级保存。
- Rust 数据模型作为业务语义的权威实现；JSON Schema、TypeScript 类型与 Zod Schema 通过生成流程或固定契约样例保持一致。

## 七、状态管理与交互

### 7.1 状态划分

| Store | 内容 | 是否持久化到项目 |
| --- | --- | --- |
| `projectStore` | 项目信息、语言配置、资源定义、对话索引 | 是 |
| `documentStore` | 当前节点、连线、脏状态 | 是 |
| `editorStore` | 选择项、视口、面板开关 | 仅必要的视口偏好 |
| `historyStore` | 撤销/重做命令栈 | 否 |
| `simulationStore` | 当前节点、临时变量、运行轨迹 | 否 |

避免建立一个包含全应用数据的巨型 Store。领域数据修改必须通过命令或明确 action 完成，React 组件不直接修改节点对象。

### 7.2 撤销与重做

- 使用命令模式记录可逆操作，不为鼠标拖动的每一帧创建历史。
- 连续文本输入在短时间内合并为一次操作，失焦后结束合并。
- 保存不会清空历史；通过保存时的历史位置判断文档是否有未保存修改。
- 切换项目时清空历史，切换对话时分别维护或恢复对应文档历史。

### 7.3 保存与恢复

- 用户保存时执行：前端整理文档 → IPC → 共享核心校验与序列化 → 存储层写入临时文件 → 刷盘 → 原子替换。
- 自动恢复快照写入应用数据目录，不污染项目仓库。
- 正常保存后清理对应快照；异常退出后再次打开应用时提示恢复。
- 检测源文件在应用外被修改的情况，提示重新加载、另存或保留当前版本，不静默覆盖。
- 关闭窗口、切换项目或退出应用时，对未保存文档进行统一拦截提示。

## 八、前后端接口

MVP 建议提供以下 Tauri Command：

| 命令 | 用途 | 关键约束 |
| --- | --- | --- |
| `create_project` | 创建项目目录和默认文件 | 目标目录必须为空或不存在 |
| `open_project` | 读取项目清单 | 返回结构化错误，不直接弹 UI |
| `read_project_file` | 读取项目内文件 | 只允许规范化后的项目相对路径 |
| `write_project_file` | 原子写入项目文件 | 禁止路径逃逸，写入前创建临时文件 |
| `validate_project` | 执行完整项目校验 | 调用 `siming-core`，返回结构化诊断 |
| `export_project` | 编译并导出运行时数据 | 有错误时拒绝导出，使用共享存储层写入 |
| `simulate_step` | 推进一次模拟运行 | 使用共享条件求值和多语言回退规则 |
| `check_migration` | 检查是否需要迁移 | 只读，不改变项目文件 |
| `migrate_project` | 备份并迁移项目 | 需要用户在桌面界面明确确认 |
| `list_recent_projects` | 读取最近项目 | 路径保存在应用配置目录 |
| `set_recent_project` | 更新最近项目 | 去重并限制记录数量 |
| `show_in_folder` | 在系统文件管理器中定位文件 | 仅允许已打开项目内路径 |

统一错误结构：

```ts
type AppError = {
  code: string;
  message: string;
  details?: Record<string, unknown>;
};
```

前端根据 `code` 决定交互，`message` 用于日志或兜底提示，避免依赖错误文案判断类型。

CLI 不经过 Tauri IPC，而是直接调用相同的 `siming-core` 和 `siming-storage` Rust crate。

## 九、安全与可靠性

- Tauri 权限按最小范围配置，只开启项目需要的文件和窗口能力。
- 所有项目相对路径在 Rust 侧规范化，并确认最终路径仍位于项目根目录内。
- CLI 对项目内部引用使用与桌面端相同的规范化与路径逃逸检查；导出只写入用户显式指定的目标目录。
- 不执行项目文件中的脚本、Shell 命令或动态加载的本地代码。
- 导入 JSON 时限制单文件大小、节点数量和嵌套深度，防止异常文件耗尽资源。
- 保存、迁移和导出使用可诊断错误，不因单个损坏对话导致整个项目无法打开。
- 日志默认不记录完整对话正文和用户本机敏感路径。

## 十、性能目标

MVP 以普通开发设备为基准，目标如下：

| 场景 | 目标 |
| --- | --- |
| 冷启动到可操作 | 3 秒以内 |
| 打开 1,000 节点的单个对话 | 2 秒以内 |
| 画布拖拽和缩放 | 主观无明显卡顿，目标 60 FPS |
| 普通编辑操作反馈 | 100 毫秒以内 |
| 1,000 节点对话完整校验 | 500 毫秒以内 |
| CLI 校验 10,000 节点项目 | 5 秒以内 |
| 项目保存 | 1 秒以内，不阻塞界面持续响应 |

实现策略：

- 只渲染可视区域内的复杂节点内容，避免无关组件重复更新。
- Zustand selector 精确订阅节点局部状态。
- 拖动过程中只更新必要位置数据，结束后再写入撤销历史。
- 校验、布局等重计算任务按需防抖；完整校验通过异步 IPC 在 Rust 后台任务中执行，避免阻塞界面线程。
- 首期不为性能提前引入数据库，以真实压测结果决定是否调整存储方式。

## 十一、测试策略

### 11.1 单元测试

- 节点和连线规则。
- 条件表达式求值与类型检查。
- 多语言回退、缺失翻译检查和稳定文本键生成。
- 源文件 Schema 校验与版本迁移。
- 源模型到运行时模型的编译结果。
- CLI 参数解析、诊断序列化和退出码映射。
- 撤销/重做命令及脏状态判断。

### 11.2 集成测试

- 前端调用 IPC 后正确处理成功和失败结果。
- 新建、读取、原子保存及外部修改冲突。
- 损坏文件、未知版本和缺失引用的错误恢复。
- 自动恢复快照的生成、恢复和清理。
- 对同一项目分别通过 Tauri Command 和 CLI 校验、导出，结果必须完全一致。

### 11.3 端到端测试

至少覆盖以下主路径：

1. 新建项目并创建一段线性对话。
2. 添加选项与条件分支并通过校验。
3. 保存、关闭、重新打开后内容和布局一致。
4. 在模拟器中修改变量并走到不同分支。
5. 切换预览语言，确认完整翻译和默认语言回退均符合预期。
6. 导出对话结构与各语言资源，并与固定运行时样例比对。
7. 制造未保存修改后退出，确认拦截与恢复行为。
8. 分别运行 CLI 的校验、导出、迁移检查和信息查询，核对 stdout、stderr 与退出码。

### 11.4 跨平台验证

- CI 至少执行 TypeScript 检查、Lint、单元测试和 Rust 测试。
- Windows、macOS、Linux 分别执行桌面应用和 CLI 构建验证。
- CI 使用构建出的 `siming` 二进制运行固定项目，验证其不依赖桌面环境。
- 每个正式版本在三平台进行一次手工冒烟测试，重点检查文件路径、快捷键和窗口行为。

## 十二、开发阶段

### 阶段 0：工程基线

- 初始化 Rust Workspace、`siming-core`、`siming-storage`、CLI、Tauri、React、TypeScript、Tailwind CSS 和测试工具。
- 建立代码检查、格式化、CI 和三平台构建流程。
- 定义源文件 Schema、示例数据和架构决策记录。

**完成标准：** 三个平台可以构建并打开空白应用，也能运行 `siming --version`；前后端 IPC 和共享核心测试通过。

### 阶段 1：可编辑闭环

- 完成项目新建、打开和保存。
- 完成对话列表、基础节点、连线、属性编辑和撤销/重做。
- 完成默认语言、支持语言配置和多语言文本字段编辑。
- 完成脏状态、退出拦截和基础错误提示。

**完成标准：** 用户能创建一段含分支及两种语言文本的对话，保存后重新打开且内容一致。

### 阶段 2：可验证闭环

- 完成全量校验、问题定位和不可达节点分析。
- 完成条件表达式编辑、变量定义和模拟运行器。
- 完成语言切换预览、默认语言回退和翻译完成度检查。
- 完成运行轨迹与无限循环保护。

**完成标准：** 用户不启动游戏即可验证同一对话在不同变量和预览语言下的分支及文本结果。

### 阶段 3：可交付闭环

- 完成运行时结构、分语言资源 JSON 编译导出、Schema 版本迁移和恢复快照。
- 完成 `validate`、`export`、`migrate`、`info` 子命令及稳定退出码。
- 完成性能优化、端到端测试、三平台桌面安装包和 CLI 压缩包。
- 提供运行时格式说明和最小接入示例。

**完成标准：** 导出数据可由独立示例程序读取、切换语言并完整走通对话；三平台桌面安装包和 CLI 均通过冒烟测试。

## 十三、MVP 验收标准

当以下条件全部满足时，MVP 可视为完成：

- 能创建并管理包含多份对话的本地项目。
- 六类节点均可通过画布创建、编辑、连接、复制和删除。
- 能配置默认语言和至少两种支持语言，并编辑对话、选项和角色名称的多语言文本。
- 撤销、重做和未保存状态在节点、连线与属性操作中行为一致。
- 保存失败不会破坏原文件，异常退出后可提示恢复未保存内容。
- 校验能识别结构错误、无效引用和不可达节点，并能定位问题。
- 模拟器能根据变量和玩家选项正确推进，且不会因死循环锁死界面。
- 模拟器能切换预览语言，缺失翻译时按照固定规则回退并清楚标记。
- 导出文件不包含画布坐标等编辑器信息，对话结构和各语言资源均通过 JSON Schema 或等价校验。
- 文本键在修改文本、移动节点和重命名对话后保持稳定，各语言资源使用同一组文本键。
- 同一输入产生稳定的导出结果，便于版本控制和自动化测试。
- CLI 能无界面执行校验、导出、迁移检查和项目信息查询，并遵守文档约定的 JSON 输出及退出码。
- 同一项目通过桌面端和 CLI 得到的诊断及导出内容一致。
- Windows、macOS、Linux 均能安装、启动、打开项目、保存和导出，并能单独运行 CLI。
- 1,000 节点基准样例达到本方案的主要性能目标。

## 十四、主要风险与应对

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 大型对话图渲染卡顿 | 编辑体验下降 | 可视区域优化、精确订阅、基准压测，必要时拆分子图 |
| 源文件格式频繁变化 | 项目文件无法兼容 | Schema 版本、顺序迁移、备份和固定样例测试 |
| 编辑状态与文件内容不一致 | 数据丢失或误覆盖 | 原子保存、脏状态、恢复快照和外部修改检测 |
| 条件系统过度复杂 | 各引擎实现不一致 | MVP 限制类型和运算符，以结构化 AST 作为唯一语义 |
| 多语言文本键随编辑变化 | 已接入翻译或配音失效 | 文本键只基于稳定 ID 生成，并添加快照测试 |
| 部分语言翻译不完整 | 玩家看到空文本 | 默认语言必填、导出前统计缺失项、运行时执行固定回退 |
| 通用格式承载过多引擎特性 | 协议失去稳定性 | 核心字段保持通用，引擎特有能力通过命名空间事件扩展 |
| 跨平台文件行为不同 | 某些平台无法保存或打开 | 统一路径处理、三平台 CI 构建和发布前冒烟测试 |
| GUI 与 CLI 行为不一致 | 本地通过但 CI 失败，或导出内容不同 | 共享 Rust 核心与存储层，并对两种入口执行契约对照测试 |
| CLI 输出混入日志 | CI 无法稳定解析 JSON | JSON 只写 stdout，日志写 stderr，并使用快照测试固定格式 |
| Tauri 与前端依赖升级不兼容 | 构建或运行受阻 | 固定 lockfile，小步升级，升级前运行完整测试矩阵 |

## 十五、后续扩展方向

MVP 稳定后可按实际项目需求评估：

- Unity、Unreal 或其他引擎的运行时 SDK 与导入器。
- CSV/XLIFF 导入导出、翻译平台同步、术语库和翻译审核状态。
- 应用界面本身的多语言切换。
- 角色立绘、语音和演出资源的预览引用。
- 子对话、函数式复用节点和跨对话跳转。
- 自定义节点与事件定义插件，但保持受控权限与数据 Schema。
- Git 差异可视化、冲突辅助处理和团队审核流程。
- 只读 Web 预览或可分享的剧情走查包。
